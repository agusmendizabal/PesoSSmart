Correr las migraciones SQL

Andá a Supabase → SQL Editor → New query, pegá cada bloque completo y ejecutalo. Primero uno, después el otro — no importa mucho el orden entre estos dos, pero corré los dos.

1a · market_rates_sync_cron.sql

Programa que el BCRA (inflación y tasas) se sincronice solo, todos los lunes. Sin esto, esos datos se quedan congelados en la fecha en que los cargaste a mano.

CREATE EXTENSION IF NOT EXISTS pg_cron;
CREATE EXTENSION IF NOT EXISTS pg_net;

SELECT cron.schedule(
  'market-rates-weekly-sync',
  '0 10 * * 1',
  $$
  SELECT net.http_post(
    url     := 'https://gqflukmlaonkgxfdbedq.supabase.co/functions/v1/fetch-market-rates',
    headers := '{"Authorization":"Bearer marketrates2026pesossmart","Content-Type":"application/json"}'::jsonb,
    body    := '{}'::jsonb
  ) AS request_id;
  $$
);
1b · chat_threads_context_fingerprint.sql

Agrega una columna a chat_threads para que el asistente sepa si tu situación financiera cambió desde la última conversación.

ALTER TABLE public.chat_threads

3b · investment-advisor

Esta es la más importante. Es la función nueva completa del asistente de inversión — todavía nunca se desplegó. Sin esto, el chat de "Alternativas de inversión" no responde.

npx supabase functions deploy investment-advisor
Cómo confirmar que quedó bien
En SQL Editor: SELECT * FROM cron.job WHERE jobname = 'market-rates-weekly-sync'; tiene que devolver una fila.
En la app: entrá a Plan Inteligente → Alternativas de inversión → mandale un mensaje al chat. Si responde, el deploy de investment-advisor funcionó.
Si el chat tira error: revisá en Supabase → Edge Functions → Logs de investment-advisor.
Esto NO hace falta tocar
  • GROQ_API_KEY ya está configurada — investment-advisor reusa la misma, no se crea una nueva.
  • Nada de INDEC ni CEDEAR — esos cron y secrets ya estaban configurados de antes y siguen vigentes.
  • No hay tablas nuevas que crear a mano: las dos migraciones del Paso 1 son las únicas.
